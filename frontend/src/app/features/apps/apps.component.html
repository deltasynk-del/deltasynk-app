How an app sends requests

Each app calls the portal with its key in the x-portal-api-key header. Sending the same id or reference again updates the request; a request staff already decided is never reopened.

Call Purpose
POST {{ ingestUrl }}/sender-ids A school or shop asked for a sender ID.
GET {{ ingestUrl }}/sender-ids/:externalId Read the decision (PENDING, APPROVED or REJECTED with the reason).
POST {{ ingestUrl }}/payments A subscription payment or SMS top-up (kind: SUBSCRIPTION or SMS_TOPUP; status: SUBMITTED when the customer has given a payment reference to verify).
GET {{ ingestUrl }}/payments/:reference Read the result — canProceed is true once staff verified it.
